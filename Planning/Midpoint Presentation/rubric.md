**Rubric**

**Grades:** H1 (80–100) | H1 (70–79) | H2.1 (60–69) | H2.2 (50–59) | Pass (40–49) | Fail (0–39)

**Project Proposal (15%)**

- **H1 (80–100):** Thoroughly researched proposal with ambitions beyond programme expectations and clear, detailed aims and objectives.
- **H1 (70–79):** Excellent, well‑researched proposal with potential commercial/real‑world relevance and clearly outlined aims/objectives.
- **H2.1 (60–69):** Strong proposal based on valid research and investigation with aims and objectives outlined in some detail.
- **H2.2 (50–59):** Good proposal, well thought out and defined; basic aims and objectives are outlined.
- **Pass (40–49):** Proposal meets minimum standards with unclear or only basic aims and objectives.
- **Fail (0–39):** Weak or missing proposal with no clear aims or objectives.

**Communication Skills (10%)**

- **H1 (80–100):** Presentation exceeds expectations; speaker is poised and enthusiastic; questions excellently answered; slides are logical and error‑free.
- **H1 (70–79):** Strong presentation; speaker poised and enthusiastic; questions very well answered; slides clear and accurate.
- **H2.1 (60–69):** Clear presentation with good delivery; questions well answered; slides logically present the argument.
- **H2.2 (50–59):** Presentation outlines the project argument and the speaker is engaged; questions reasonably well answered.
- **Pass (40–49):** Presentation is disorganised or unclear and questions are poorly answered.
- **Fail (0–39):** Presentation fails to communicate the project and questions are unanswered.

**Project Analysis & Planning (10%)**

- **H1 (80–100):** Challenging aspects identified with conceptual diagrams and alternative solutions; project plan maps processes to detailed tasks, milestones and activities beyond expectations.
- **H1 (70–79):** Challenging aspects understood and evidenced by conceptual diagrams; project plan maps processes to appropriate tasks, milestones and activities.
- **H2.1 (60–69):** Challenging aspects understood with some conceptual evidence; plan maps most processes to tasks and milestones.
- **H2.2 (50–59):** Project plan maps most processes to tasks/milestones with some detail and some solutions identified.
- **Pass (40–49):** Project plan maps some processes to tasks and milestones but lacks detail and few solutions are identified.
- **Fail (0–39):** Little or no breakdown of tasks, milestones or solutions; difficult aspects not addressed.

**Requirements Engineering (40%)**

- **H1 (80–100):** Outstanding, systematic and iterative requirements documentation detailing all functional and non‑functional requirements and user interactions, exceeding programme expectations.
- **H1 (70–79):** Systematic and iterative requirements documentation detailing functional and non‑functional requirements and how users interact with the system.
- **H2.1 (60–69):** Systematic requirements documentation covering the key functional and non‑functional requirements and basic user interaction.
- **H2.2 (50–59):** Requirements documentation detailing most functional and non‑functional requirements and user interaction.
- **Pass (40–49):** Ad hoc requirements gathering and documentation covering a limited set of functional and/or non‑functional requirements.
- **Fail (0–39):** Inadequate or missing requirements gathering and documentation.

**Prototype (25%)**

- **H1 (80–100):** Working demonstration that gives a complete visual understanding of functionality and user interaction, with multiple core features fully implemented.
- **H1 (70–79):** Working demonstration providing a visual understanding of all application functionality with several core elements implemented.
- **H2.1 (60–69):** Working demonstration showing core functionality and how the user interacts, with some basic features implemented.
- **H2.2 (50–59):** Working demonstration showing some functionality and basic user interaction with limited implemented features.
- **Pass (40–49):** Partial demonstration that gives a limited visual understanding of functionality and interaction.
- **Fail (0–39):** Demonstration does not provide a visual understanding of system functionality or user interaction.
